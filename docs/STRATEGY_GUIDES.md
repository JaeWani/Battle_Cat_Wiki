# 내 계정 맞춤 공략과 유사 조건 검색

## 이용 경로

게시판 → **공략 등록** → 비밀번호 설정 → 제목·본문 작성 → **구조화된 공략으로 등록**을 선택합니다. 한국판 스테이지와 성급, 작성자가 기록한 결과(클리어/실패/시도), 편성 1~10종의 형태·기본/+레벨·역할·본능, 보물과 아이템 조건을 입력하고 공개 확인 후 게시합니다. 선택 캐릭터의 내 정보만 불러오는 버튼을 제공하며, 전체 게임 프로필을 자동 게시하지 않습니다. 본능은 미기재·0·레벨을 구분합니다. 실제 운용 순서, 냥콤보, 대포, 실패 지점 등은 본문에 적습니다.

공략 상세의 **내 계정으로 도전 준비**를 누르면 저장된 한국판 캐릭터와 비교합니다. 미보유·기본/+레벨·총 레벨·선택 형태 차이, 기재된 본능 부족/미확인, 보물 조건과 아이템 확인 사항을 표시합니다. 내 정보의 현재 선택 형태는 최종 진화 해금 여부와 다를 수 있으므로 직접 확인해야 합니다.

대체 후보는 내가 보유한 현재 선택 형태만 사용합니다. 역할, 기본 대상 속성, 기본 능력·면역과 사거리/가격/쿨타임을 기준으로 최대 3종을 제안합니다. 전선 유지는 가격·쿨타임, 방해는 공통 방해 능력, 특수 대응은 기본 능력/면역 공통점, 화력은 직접 공격 존재를 검사합니다. 필요한 정보나 공통점이 없으면 후보를 제시하지 않습니다. 본능으로 바뀐 능력이나 전투 전체를 계산하지 않습니다. 누락된 기본 능력·면역, 짧아진 사거리와 미검증 범위를 함께 보여줍니다.

후보를 선택하면 **내 편성 초안**에 반영하고 복사할 수 있습니다. 미해결 슬롯과 슬롯 순서를 유지하며 중복 선택을 막습니다. 계정 게임 데이터나 원본 공략을 변경하지 않습니다. 원본과 대체 편성 모두 게임 계정으로 인증한 기록이 아닙니다.

게시판 → **맞춤 공략 찾기**에서 스테이지·성급·제목·작성자 결과를 필터링합니다. 기본은 클리어 자기보고 기록이며 실패/시도 기록 또는 전체를 선택할 수 있습니다. 로그인한 사용자는 **내 편성 조건과 가까운 순**으로 정렬할 수 있습니다. 등록된 공개 공략이 없으면 빈 상태와 등록 경로를 표시합니다. 샘플 공략이나 클리어 실적을 실제 사용자 데이터로 만들어 넣지 않습니다.

## 유사 정렬

서버는 요청자의 비공개 한국판 게임 프로필만 읽고 공개된 전체 검색 대상에 대해 점수를 계산한 뒤 페이지를 반환합니다(페이지당 20개, 다음 페이지 확인용 1개 추가). 임의 `user_id`는 무시합니다. 점수는 캐릭터 슬롯별 차이의 평균입니다.

- 미보유: 슬롯 1,000점
- 보유: 총 레벨 차이 절댓값 + 현재 선택 형태가 공략보다 낮으면 20점
- 공략에 기재된 각 본능: 내 기록이 없으면 10점, 있으면 레벨 차이 절댓값 × 5점

낮을수록 기록된 편성 조건이 가깝습니다. 승률·캐릭터 성능 점수·클리어 가능 판정이 아닙니다. 보물, 아이템 보유량, 냥콤보, 대포, 입장 자격, 플레이 방식, 미기재 본능은 순위에 반영하지 않으며 상세 비교에서 확인합니다. 기록이 상세하지 않은 공략은 추가 확인이 필요합니다. 익명은 최신순 공개 검색을 이용하고, 유사 정렬에는 로그인·정상 회원·한국판 프로필이 필요합니다.

## 저장·권한·공개 범위

`noc_private.strategy_guides`는 게시글에 종속된 공개용 조건만 저장합니다. 모든 테이블은 RLS+직접 접근 거부 정책과 권한 회수를 적용합니다. 공개 읽기는 기존 `noc_api('post')`와 새 `noc_api('list_guides')`로만 제공합니다. 초안·숨김·삭제 글은 공개 공략 검색에서 제외합니다. 상세는 기존 게시글 접근 검사를 먼저 수행합니다.

기존 비밀번호 검증을 통과한 `save_post` 안에서 게시글과 조건을 같은 트랜잭션으로 저장합니다. `strategy: null`은 조건 제거이며, 키 생략은 기존 조건 유지입니다. 작성자·정상 회원·게시 상태·공략 게시판과 공개 확인을 다시 검사합니다. 미등록 스테이지/캐릭터/형태, 중복 편성·본능, 본능 상한, 잘못된 숫자/결과/아이템/보물 조건을 거부하고 이메일·인계 코드 등 추가 필드는 제거합니다. 기본 레벨 1~200, +레벨 0~1,000은 저장 형식의 상한이며 실제 게임의 캐릭터별 해방 조건을 검증하는 것은 아닙니다.

게시글 삭제·탈퇴의 삭제 상태 전환 시 트리거가 공개 공략 조건을 삭제합니다. 숨김에서는 접근을 차단하고 조건을 비공개로 유지하므로 복구할 수 있습니다. 계정 전환·로그아웃·화면 이탈 시 비교에 사용한 개인 프로필 메모리와 표시된 비교 결과를 정리합니다. 전체 계정 데이터를 공개하거나 타인의 프로필을 조회하는 API를 추가하지 않았습니다.

## 검증

- `supabase/tests/strategy_guides.sql`: 실제 PostgreSQL 트랜잭션/롤백 검증. 저장·공개 필드 제한, 무효 값과 원자성, 비밀번호·작성자 검사, 스테이지/성급/결과 검색, 본인 프로필 정렬, 타인 ID 주입 무시, 익명 거부, 직접 테이블/도우미 거부, 숨김·삭제·탈퇴, 공략 조건 제거를 검사합니다. 가상 계정·공략은 남기지 않습니다.
- 기존 비밀번호·게시판 권한/운영·수동 게임 데이터·프로필 이미지 SQL 검증도 통과했습니다.
- `tests/strategy.test.mjs`: 모델 검증, 개인정보 필드 제거, 중복/상한 거부, 부족/미확인 설명, 차이 점수, 프로필 불변성, 대체 후보 보유/제외/검증 한계를 검사합니다.
- 실제 Chrome: 운영 UI 모듈을 격리된 인증 어댑터로 실행해 공략 작성·공개 확인·비밀번호 전달, 비교, 대체 초안, 계정 데이터 미수정, 유사 정렬, 결과 필터, PC/모바일 화면과 계정 전환 시 결과 제거를 검사합니다. 이 어댑터를 실계정 Google 로그인 검증이라고 주장하지 않습니다.
